# StorePOS 1.1: უსაფრთხო განახლება და დაბრუნება RC3-ზე

ეს ინსტრუქცია ეხება მაღაზიის ნამდვილ კომპიუტერს, სადაც RC3 „ყველა მომხმარებლისთვისაა“ დაყენებული (`C:\Program Files\StorePOS`). ყოველი ნაბიჯი შემოწმებულია ტესტში ძველი RC3-ის ნამდვილი პროგრამით (`e2e/downgrade-guard-test.mjs`, [V1.1_RELEASE_READINESS.md](V1.1_RELEASE_READINESS.md) §12). გამონაკლისია მხოლოდ „ყველა მომხმარებლისთვის“ ინსტალაციის რეჟიმი: ის ტესტში არ გაშვებულა.

## რას იცავს RC2

განახლების შემდეგ ბაზაში ჩაშენებულია დაცვა. თუ ძველი RC3 პროგრამა ამ ბაზას გახსნის:

- RC3 ჩაირთვება და მონაცემებს აჩვენებს. მფლობელი და გამყიდველი შედიან.
- **ვერაფერს ცვლის**: გაყიდვა, მიღება, აღწერა, დაბრუნება, გაცვლა, დაფარვა, ჩამოწერა, პროდუქტი, ფასი, ფოტო, კატეგორია, კლიენტი, ხარჯი, პერსონალი, PIN, ბაზის გასუფთავება. ყოველ ცდაზე ჩნდება შეცდომა `no such function: requires_storepos_v1_1`. ბაზაში არაფერი ჩაიწერება.
- RC3-ს მაინც შეუძლია: საკუთარი backup-ის შექმნა და აღდგენა, პარამეტრების შენახვა, ჟურნალებში ჩაწერა. ეს ნაშთს, თვითღირებულებას და ფულს არ ეხება.

თუ ეს შეცდომა RC3-ში ნახეთ, დახურეთ RC3 და გაუშვით StorePOS 1.1. თუ RC3 თავიდან დადგა, დააინსტალირეთ RC2 ხელახლა. მონაცემები ხელუხლებელია.

## ინსტალაციამდე

1. RC3-ში გახსენით **პარამეტრები** და დააჭირეთ **„სარეზერვო ასლის შექმნა ახლავე“**. ჩაიწერეთ ფაილის სახელი, მაგ. `storepos_manual_2026-11-22_09-30-00-000.posbackup`. **ეს არის დასაბრუნებელი ასლი.**
2. ეს ფაილი დააკოპირეთ USB-ზე. ფაილები ინახება `%APPDATA%\StorePOS\data\backups`-ში, ან იქ, სადაც backup-ის საქაღალდე გაქვთ არჩეული.
3. დახურეთ RC3.
4. შეამოწმეთ ინსტალერი PowerShell-ში:
   ```powershell
   Get-FileHash .\StorePOS-Setup-1.1.0-rc.2.exe
   ```
   შედეგი უნდა იყოს `69E54492BA2C9E2C98756D29DFAA63B9EAC78677771E171C85BA22F224599DEB`.

## ინსტალაცია

5. გაუშვით `StorePOS-Setup-1.1.0-rc.2.exe`. ინსტალაციის რეჟიმის გვერდზე დატოვეთ წინასწარ მონიშნული **„ყველა მომხმარებლისთვის“** (Anyone who uses this computer). დაადასტურეთ Windows-ის კითხვა (UAC). RC3 ადგილზე ჩანაცვლდება.
6. გაუშვით StorePOS. შესვლის ეკრანზე უნდა ჩანდეს ვერსია `1.1.0-rc.2`. Start მენიუში უნდა იყოს მხოლოდ ერთი StorePOS.
7. შედით მფლობელით და შეადარეთ RC3-ს: პროდუქტების რაოდენობა, ნისიის ჯამი, დღევანდელი გაყიდვები.
8. მაშინვე გააკეთეთ ახალი backup V1.1-ში.

პირველ გაშვებაზე ბაზა V1.1-ზე გადადის. მანამდე პროგრამა ავტომატურად ქმნის ასლს: `store.db.before_migration_v7_<დრო>.bak`, მონაცემების საქაღალდეში.

## განახლების შემდეგ

- RC3-ის ინსტალერი აღარ გაუშვათ.
- ძველი backup-ები ძალაშია. V1.1 RC3-ის backup-საც აღადგენს.

## დაბრუნება RC3-ზე (მხოლოდ თუ V1.1-ში ხელისშემშლელი პრობლემაა)

**მნიშვნელოვანი:** დაბრუნებისას მაღაზია ბრუნდება ინსტალაციამდე გაკეთებული ასლის მდგომარეობაზე. V1.1-ში შემდეგ შეყვანილი გაყიდვები და მიღებები RC3-ში არ გადავა. ისინი რჩება V1.1-ის მონაცემების ასლში (ნაბიჯები R1 და R4), და მათი დაბრუნება V1.1-ში შესაძლებელია („დაბრუნების გაუქმება“ ქვემოთ).

R1. V1.1-ში გააკეთეთ backup და დააკოპირეთ USB-ზე.

R2. დააინსტალირეთ `StorePOS-Setup-1.0.0-rc.3.exe` (SHA-256 `8279403A92E1FEE4CA5FDF401A8C6F14C58BBFE8483391D8D540DA12403F94A5`), იმავე რეჟიმში („ყველა მომხმარებლისთვის“).

R3. გაუშვით RC3 და შედით მფლობელით (PIN იგივეა). RC3 აჩვენებს V1.1-ის მონაცემებს, მაგრამ შეცვლას ვერ შეძლებს. ეს მოსალოდნელია.

R4. **პარამეტრები** → ასლების სიაში მოძებნეთ ნაბიჯი 1-ის ფაილი (ინსტალაციამდე გაკეთებული) → მის გასწვრივ **„აღდგენა“**. RC3 აღდგენამდე ავტომატურად ინახავს მიმდინარე (V1.1) მონაცემებს ფაილად `storepos_prerestore_<დრო>.posbackup`.

R5. ხელახლა შედით. RC3 ჩვეულებრივ მუშაობს ინსტალაციამდელი მონაცემებით.

V1.1-ის მიერ გაკეთებულ backup-ს RC3 არ აღადგენს („შექმნილია უფრო ახალი ვერსიით“). ასე შემთხვევით არასწორ ასლს ვერ აირჩევთ.
