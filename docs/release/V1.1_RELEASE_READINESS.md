# StorePOS 1.1.0-rc.2: მზადყოფნის ანგარიში

თარიღი: 2026-11-21. Branch: `feature/storepos-v1.1` (GitHub-ზე ატვირთულია ცალკე branch-ად თქვენი თანხმობით; `main`-ში merge **არ** მომხდარა). საწყისი: RC3 `3f4f65d`. RC2-ის კოდი: commit `d3a3de0`. ეტაპების დეტალები: [../V1.1_PROGRESS.md](../V1.1_PROGRESS.md). განახლებისა და დაბრუნების ინსტრუქცია: [V1.1_UPGRADE_AND_ROLLBACK.md](V1.1_UPGRADE_AND_ROLLBACK.md).

## 1. დასკვნა

**1.1.0-rc.2 მზადაა იზოლირებული ხელით შემოწმებისთვის, საბოლოო ვერსიად ჯერ არა.** RC2 ცვლის RC1-ს. RC1-თან შედარებით მასში ერთი ცვლილებაა: დაცვა ძველი RC3 პროგრამისგან (§12).

- **დაცვა ძველი RC3-ისგან მუშაობს. შემოწმებულია ძველი RC3-ის ნამდვილი პროგრამით** (`StorePOS.exe`, ამოღებული RC3-ის ინსტალერიდან `8279403a…`). RC3 V1.1-ის ბაზაზე ირთვება და მონაცემებს აჩვენებს, მაგრამ მისი 30-ვე ოპერაცია, რომელიც ნაშთს, თვითღირებულებას, ფულს, ნისიას, დაბრუნებას, პროდუქტს, კლიენტს ან პერსონალს ცვლის, უარყოფილია. ბაზის გასუფთავებაც. ამ ცხრილებში არცერთი სტრიქონი არ შეიცვალა. V1.1-ის ხელახლა გახსნის შემდეგ ყველა ციფრი იდენტურია (§12.3).
- **დაბრუნება RC3-ზე** შემოწმებული პროცედურით მუშაობს: RC3 ინსტალაციამდე გაკეთებულ backup-ს აღადგენს და ზუსტად RC3-ის მაღაზიას აბრუნებს. დაბრუნების გაუქმებაც შესაძლებელია: V1.1 RC3-ის ავტომატურ ასლს აღადგენს და V1.1-ის მონაცემები ზუსტად ბრუნდება (§12.4).
- **იზოლირებულად შესამოწმებლად გამოიყენეთ `StorePOS-Test-Setup-1.1.0-rc.2.exe`** (§9). პროგრამის ფაილები RC2-ისაა. განსხვავდება მხოლოდ სახელი (§12.5). **`StorePOS-Setup-1.1.0-rc.2.exe` ამ კომპიუტერზე იზოლირებული არ არის**: ის „ყველა მომხმარებლისთვის“ დაყენებულ RC3-ს ჩაანაცვლებს (§11.4).
- ყველა ტესტი ხელახლა გაეშვა RC2-ის ინსტალერიდან ამოღებულ პროგრამაზე (§4). ტესტების მხარეს ნაპოვნი და გასწორებული: ჩემი შეჯერების ფორმულა დაბრუნების ხაზზე არასწორი იყო. აპლიკაცია სწორად ითვლის (§12.6).
- შეუმოწმებელი რჩება: „ყველა მომხმარებლისთვის“ (UAC) ინსტალაციის რეჟიმი, Windows-ის ნამდვილი ძილი, ფიზიკური მოწყობილობები (§7, §8).
