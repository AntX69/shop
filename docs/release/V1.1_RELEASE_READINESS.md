# StorePOS 1.1.0-rc.1: მზადყოფნის ანგარიში

თარიღი: 2026-11-20. Branch: `feature/storepos-v1.1` (ლოკალური, GitHub-ზე **არ არის** ატვირთული). საწყისი: RC3 `3f4f65d`. ეტაპების დეტალები: [../V1.1_PROGRESS.md](../V1.1_PROGRESS.md).

## 1. დასკვნა

**1.1.0-rc.1 მზადაა თქვენი ხელით შემოწმებისთვის (Release Candidate), საბოლოო ვერსიად ჯერ არა.** ავტომატური ტესტებიდან ყველა გავიდა ერთის გარდა: 30-წუთიან soak-ში ჩავარდა ავტომატური backup-ის დროის შემოწმება, რისი მიზეზიც ტესტის საკუთარი 30-წამიანი გაყინვაა და არა აპლიკაცია (§4.2). საბოლოო ვერსიამდე დარჩა: თქვენი ხელით შემოწმება, ფიზიკური მოწყობილობები (§7) და გადაწყვეტილება push/merge-ზე.

RC3 თქვენს კომპიუტერზე **არ შეცვლილა**: V1.1 არ დაინსტალირებულა; ინსტალაციის და განახლების ტესტები ჩატარდა ცალკე სატესტო იდენტობით („StorePOS-Test“: სხვა საქაღალდე, სხვა რეესტრის ჩანაწერი, სხვა მონაცემები).

- ყოველი IPC არხი (60+) ტესტით შემოწმდა ორივე მიმართულებით: გამყიდველი უფლების გარეშე → უარი, უფლებით → გადის. სიაში არმყოფი ღია არხი ტესტს ჩააგდებს. ყველა უფლების მქონე გამყიდველიც ვერ იძახებს მფლობელის არხებს.

## 6. FIFO და ბუღალტრული შეჯერება

- ფორმულა: ნაწილის ღირებულება = დარჩენილი ღირებულება × აღებული / დარჩენილი (უახლოეს ტეტრამდე), ბოლო ნაწილი = ზუსტი ნარჩენი. ცალობრივისთვის RC3-ის იდენტური.
- სიმულაცია (205 პროდუქტი, 88 გაყიდვა, 23 დაბრუნება, 6 გაცვლა ცალი↔კგ, 16 დაფარვა, კორექციები, backup/აღდგენა): ფინანსების ციფრები (წმინდა გაყიდვები, ნაღდის ნაკადი, COGS, უკუგატარება, მარაგის ღირებულება, ნისია, ხარჯები) **ზუსტად ემთხვევა** დამოუკიდებელ SQL-ს; მოძრაობების ღირებულების ჯამი = თაროს ღირებულება 218 ვარიანტზე (0 შეუსაბამობა); აღდგენამ ზუსტად backup-ის მდგომარეობა დააბრუნა.
