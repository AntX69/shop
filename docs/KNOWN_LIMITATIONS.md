# Known Limitations: StorePOS 1.0.0-rc.2

## აპარატურა
- USB სკანერი და ვებკამერის OCR: Software Verified / Hardware Pending (ფიზიკურად შეუმოწმებელი). სკანერისთვის საჭიროა USB HID (კლავიატურის) რეჟიმი; COM/Serial რეჟიმი არ არის მხარდაჭერილი. შტრიხკოდი მხოლოდ ციფრებია.
- DATECS DP-150 ფისკალური აპარატი — არ არის ინტეგრირებული; ფისკალური ჩეკი არ იბეჭდება.
- OCR იყენებს MNIST მოდელს: ერთი ციფრი თითო უჯრაში, მკაფიო ხელწერა; შედეგი ყოველთვის მოწმდება/სწორდება ხელით. რეალური სიზუსტე ჯერ უცნობია (საველე ტესტი: `docs/hardware/OCR_FIELD_TEST_KA.md`).

## უსაფრთხოება
- ინსტალერი და პროგრამა ციფრული ხელმოწერის გარეშეა → SmartScreen-ის გაფრთხილება პირველ გაშვებაზე.
- `.posbackup` ფაილი დაშიფრული არ არის; ბაზა დისკზე დაშიფრული არ არის (რეკომენდებულია BitLocker და Windows-ის პაროლი).
- 4–6 ციფრიანი PIN დაცულია online lockout-ით; ბაზის ასლზე offline შერჩევისგან ვერ დაიცავს.
- Owner-ის PIN-ის აღდგენა პროგრამაში არ არის — გყავდეს მეორე Owner.
- Git-ის ისტორიაში რჩება AI Studio-ს სატესტო ბაზა (Owner-ის PIN ჰეშით), 15 სატესტო backup და ძველი build (მიმდინარე ხიდან ამოღებულია; დეტალები: `docs/release/SECURITY_PRIVACY_REVIEW.md`).
- Chromium-ის `--remote-debugging-port` პარამეტრი არ არის დაბლოკილი: ირთვება მხოლოდ მაშინ, თუ პროგრამას ამ კომპიუტერზე ვინმე ამ პარამეტრით გაუშვებს, და მხოლოდ 127.0.0.1-ზე. ავტომატური ტესტები ამით მართავს რეალურ პროგრამას.

## ტესტირება
- შემოწმებულია Windows 11 Pro-ზე; Windows 10: არა.
- ხანგრძლივი მუშაობა: 2-საათიანი soak (10 117 გაყიდვა) გავიდა. მრავალდღიანი უწყვეტი მუშაობა ჯერ არ შემოწმებულა. renderer-ის JS heap ≈ +3,6 MB/სთ; რეკომენდებულია დღის ბოლოს პროგრამის დახურვა.
- გარჩევადობა/მასშტაბი შემოწმებულია ემულაციით (10 კომბინაცია), არა ფიზიკურ ეკრანებზე.
- ხელით შემოწმება: შენი განცხადებით, ძირითადი ფუნქციები მუშაობს. RC2-ის ახალი ელემენტები (სკანერის რიგი, კამერის ინსტრუქციები) ავტომატურადაა შემოწმებული, ხელით ჯერ არა.

## ტექნიკური
- ძველი სატესტო მონაცემების რეპარაცია მიგრაციაში: M12-ის დროს გაცვლით წაშლილი ნისიები უკან არ აღდგება (ისტორიული ჩანაწერები არ შეცვლილა); ახალი ოპერაციები სწორად აღირიცხება.
- სესიები მეხსიერებაშია: პროგრამის გადატვირთვა ყველას გამოიყვანს (განზრახ).
- ავტომატური ასლი კეთდება მხოლოდ მაშინ, როცა პროგრამა ჩართულია (დღეში ერთხელ, დღის დასაწყისში, სალაროს სიჩუმის მომენტში). დღის ბოლოს საჭიროა ხელით ასლი.

- თუ ბაზა დაზიანებულია, პროგრამა არ ირთვება და ფაილს არ ეხება. ასლის აღსადგენად საჭიროა ფაილის ხელით გადარქმევა (`docs/DISASTER_RECOVERY_KA.md`, სცენარი C).
- გაშვების შეცდომის ფანჯრის სათაური ინგლისურია („Error“), ტექსტი ქართული.
