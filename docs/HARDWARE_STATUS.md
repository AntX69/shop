## DATECS DP-150 — ინტეგრაციის გეგმა (გადაწყვეტილებები, არა ბრძანებები)

მიღებული მასალები (`KasaGE.dll`, SDK Sample, `KasaGE.xml`, DP-25 პროტოკოლის PDF) ამ რეპოზიტორიაში **არ არის** და ვერ შევამოწმე. პროტოკოლის ბრძანებები, კაბელის pinout ან პარამეტრები არ გამომიგონია.

1. **თავსებადობა:** Kasa.ge-სგან წერილობით დადასტურება, რომ `KasaGE.dll`/DP-25 ბრძანებები მოქმედებს DP-150-ზე (მოდელი, firmware).
2. **კავშირი:** რომელი პორტი (RS-232 / USB-serial / USB), კაბელის ტიპი, COM პარამეტრები — მწარმოებლის დოკუმენტიდან.
3. **ტექნოლოგია:** `KasaGE.dll` არის .NET ბიბლიოთეკა (გადასამოწმებელი). Electron-იდან გამოძახება ცალკე პატარა .NET პროცესით (stdin/stdout JSON), რომელიც მხოლოდ `FiscalPrinter` ინტერფეისს ასრულებს — main process-ში native .NET ჩატვირთვის გარეშე.
4. **წესები (უკვე ჩადებულია ინტერფეისში):** ჩეკი იბეჭდება მხოლოდ SQLite-ის commit-ის შემდეგ; ერთ გაყიდვაზე/დაბრუნებაზე ერთი ფისკალური დოკუმენტი (UNIQUE ჩანაწერი); შეცდომისას — „მოლოდინში“ და ხელით, აღრიცხული ხელახლა ცდა; ორმაგი ბეჭდვის აკრძალვა.
5. **ტესტი:** ჯერ მწარმოებლის სატესტო/სასწავლო რეჟიმში, შემდეგ ერთი რეალური ჩეკი, X-ანგარიში, დაბრუნების ჩეკი, Z-ანგარიში.
6. **იურიდიული:** ნისიით, შერეული და გაცვლის ჩეკების ფისკალური ასახვის წესი — დასადასტურებელია ბუღალტერთან / Kasa.ge-სთან.
