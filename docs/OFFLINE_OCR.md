# StorePOS — 100% Offline Handwritten 5-Digit OCR Pipeline

---

## 1. მოდელის დანიშნულება და მოთხოვნები

საცალო მაღაზიებში (ტანსაცმელი, ფეხსაცმელი, აქსესუარები, სათამაშოები) პროდუქტების ნაწილს არ აქვს ქარხნული შტრიხკოდი, ამიტომ გამყიდველები იარლიყზე ხელით აწერენ **ზუსტად 5-ნიშნა კოდს** დიაპაზონში `10000–99999`.

StorePOS OCR მოდულის მთავარი პრინციპები:
- **სრულიად ოფლაინ ONNX ნეირონული ქსელი:** იყენებს ლოკალურად ჩაშენებულ გაწვრთნილ ONNX მოდელს (`public/models/mnist.onnx`), არ საჭიროებს ინტერნეტს, გარე API-ს ან Cloud სერვისს.
- **მკაცრი ვალიდაცია:** კოდი უნდა შედგებოდეს ზუსტად 5 ციფრისგან (`^\d{5}$`).
- **ნულოვანი ფეიკი/რანდომი:** არ გამოიყენება მოგონილი ან შემთხვევით გენერირებული ამოცნობის შედეგები — მხოლოდ რეალური ტენზორული ინფერენსი Softmax ალბათობებით.
- **სავალდებულო დადასტურება:** ამოცნობის შედეგი **არასდროს ემატება კალათაში ავტომატურად**. ეკრანზე ჩნდება პროდუქტის ბარათი, რომელსაც გამყიდველი ამოწმებს და ადასტურებს ღილაკით "დადასტურება და დამატება".
- **კამერის ალტერნატივა & Hardware Verification:** კამერის არქონისას ან უსაფრთხოების შეზღუდვისას სისტემა აჩვენებს სტატუსს `Pending Hardware Verification`, პროგრამა ჩვეულებრივ აგრძელებს მუშაობას და გამყიდველს ყოველთვის შეუძლია კოდის ხელით აკრეფა, ფოტოს ატვირთვა ან USB შტრიხკოდის სკანერის გამოყენება.

## 2. გამოსახულების დამუშავების ეტაპები (Pipeline)

1. **ვებკამერის ნაკადი & ROI (Region of Interest):**
   - ვიდეო ნაკადიდან ამოიჭრება ცენტრალური მართკუთხა ზონა (5-ნიშნა კოდის ვიზუალური ჩარჩო).
   - მომხმარებელს ეკრანზე უჩანს 5-სექციიანი გზამკვლევი ბადე.
2. **ნაცრისფერი გარდაქმნა (Grayscale):**
   - $Y = 0.299 \cdot R + 0.587 \cdot G + 0.114 \cdot B$.
3. **ადაპტური ბინარიზაცია (Otsu's Thresholding):**
   - ავტომატურად ითვლის ოპტიმალურ ზღვარს ფონისა და ხელნაწერის კონტრასტისთვის.
   - პიქსელები გარდაიქმნება ბინარულ მატრიცად (მელანი: 1.0, ფონი: 0.0).
4. **ციფრების სეგმენტაცია (Digit Segmentation):**
   - ჰორიზონტალური და ვერტიკალური პროექციული ჰისტოგრამების (Projection Histograms) გამოყენებით გამოსახულება იყოფა 5 ცალკეულ ციფრის ბლოკად.
   - თითოეული ციფრის კონტური იჭრება და ცენტრირდება სტანდარტულ $28 \times 28$ Float32 ტენზორზე (MNIST ნორმალიზაცია).
5. **ONNX ნეირონული ქსელის ინფერენსი (InferenceSession):**
   - თითოეული ციფრის ტენზორი მიეწოდება ONNX მოდელს: `[1, 1, 28, 28]`.
   - მოდელი აბრუნებს 10 ლოგიტს (0-დან 9-მდე ციფრებისთვის).
   - გამოიყენება რიცხობრივად მდგრადი Softmax ფუნქცია ალბათობების დასათვლელად:
     $$P(d) = \frac{e^{z_d - \max(z)}}{\sum_j e^{z_j - \max(z)}}$$
   - გამარჯვებული ციფრი განისაზღვრება $\text{argmax}(P)$, ხოლო სანდოობა არის $\max(P) \times 100\%$.
6. **ლოკალური სარეზერვო კლასიფიკატორი (Fallback):**
   - თუ ONNX სესია რაიმე მიზეზით ხელმიუწვდომელია, ამოქმედდება ტოპოლოგიური სტრუქტურული ანალიზი (მარყუჟები, მასის ცენტრი, სიმკვრივე).

## 3. Windows Installer Packaging

მოდელის ფაილი ინახება ლოკალურად:
- `public/models/mnist.onnx`
- `electron-builder.yml`-ში კონფიგურირებულია `extraResources`, რათა Windows NSIS ინსტალერმა მოდელი ავტომატურად ჩაალაგოს სამიზნე კომპიუტერზე:
  ```yaml
  extraResources:
    - from: public/models
      to: models
      filter:
        - "**/*"
  ```
- გაშვებისას `OcrService.getModelPath()` ავტომატურად პოულობს ფაილს როგორც საინსტალაციო `resources/models/mnist.onnx`-ში, ისე `public/models/mnist.onnx`-ში.

## 4. UI ინტერაქცია და ხელით კორექცია

1. ამოცნობის შემდეგ ეკრანზე გამოისახება **5 რედაქტირებადი უჯრა**.
2. თუ ამოცნობის სანდოობა დაბალია (<70%), მომხმარებელს ეძლევა გაფრთხილება: *"ამოცნობის სანდოობა დაბალია (<70%). გთხოვთ გადაამოწმოთ და საჭიროების შემთხვევაში ხელით შეასწოროთ 5-ნიშნა კოდი."*
3. გამყიდველს შეუძლია კლავიატურით მყისიერად ჩაასწოროს ნებისმიერი ციფრი.
4. სისტემა დაუყოვნებლივ ამოწმებს 5-ნიშნა კოდს მაღაზიის კატალოგში (`products:lookupCode`):
   - თუ პროდუქტი მოიძებნა: გამოჩნდება პროდუქტის დასახელება, ვარიანტი, ფასი და მარაგის ნაშთი.
   - პროდუქტი კალათაში ემატება მხოლოდ მაშინ, როცა გამყიდველი დააჭერს ღილაკს **"დადასტურება და დამატება"**.
