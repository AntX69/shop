# StorePOS — ხელნაწერი 5-ნიშნა კოდის offline ამოცნობა (OCR)

**სტატუსი:** Software Verified / Hardware Pending. მოდელი, კამერის ციკლი და ხელით შესწორება ტესტირებულია დაყენებულ პროგრამაში, ვირტუალური კამერებით (`e2e/hardware-readiness.mjs`). რეალური ვებკამერით და ხელნაწერით სიზუსტე ჯერ **უცნობია**. საველე ტესტი: [hardware/OCR_FIELD_TEST_KA.md](hardware/OCR_FIELD_TEST_KA.md).

## 1. დანიშნულება

პროდუქტებს, რომლებსაც ქარხნული შტრიხკოდი არ აქვს, მფლობელი ხელით ანიჭებს 5-ნიშნა კოდს (10000–99999). გამყიდველს შეუძლია ეს კოდი კამერით წაიკითხოს. პრინციპები:

- მთლიანად offline: ONNX მოდელი პროგრამაშია, ინტერნეტი და გარე API არ გამოიყენება.
- შედეგი **არასდროს** ემატება კალათაში ავტომატურად: ჩნდება 5 უჯრა (SmartDigitInput) და პროდუქტის ბარათი; დამატება — მხოლოდ დადასტურებით.
- ყალბი/შემთხვევითი შედეგი არ არსებობს. თუ მოდელი ვერ ჩაიტვირთა, ჩანს შეცდომა და კოდი შეიყვანება ხელით ან სკანერით (სარეზერვო „სტრუქტურული“ კლასიფიკატორი არ გამოიყენება).

## 2. მოდელი

- `public/models/mnist.onnx` — ONNX Model Zoo-ს MNIST (CNTK 2.5.1), 26 454 ბაიტი, შესასვლელი `Input3` `[1, 1, 28, 28]`, გამოსასვლელი 10 ლოგიტი.
- გაშვება **main process**-ში, `onnxruntime-web` WASM backend-ით, ერთ ნაკადად (`numThreads = 1`).
- მოდელს გადაეცემა ფაილის ზუსტი ბაიტები (`new Uint8Array(buf.buffer, buf.byteOffset, buf.byteLength)`). M12-მდე გადაეცემოდა `buf.buffer` (Node-ის 64 KB-იანი საერთო buffer) და Electron-ში მოდელი საერთოდ ვერ იტვირთებოდა.

## 3. დამუშავება (`src/main/domain/ocrService.ts`)

1. Renderer: კამერის კადრიდან ამოიჭრება 5-უჯრიანი ჩარჩოს ზონა (65% × 28%; ეკრანის მწვანე ჩარჩო ამ ზონაში ეტევა). RGBA პიქსელები IPC-ით (`ocr:recognize`) typed array-ით იგზავნება main process-ში. 2 მეგაპიქსელზე დიდი ზონა (მხოლოდ ატვირთული ფოტო) ჯერ პროპორციულად მცირდება. main process ზომას და სიგრძეს ამოწმებს.
2. ნაცრისფერი: `Y = 0.299R + 0.587G + 0.114B`.
3. ბინარიზაცია: Otsu-ს ზღვარი (−10, შეზღუდული 50–220); მელანი = 1, ფონი = 0.
4. სეგმენტაცია: სვეტების პროექცია; თუ ზუსტად 5 ბლოკი არ მოიძებნა — 5 თანაბარი უჯრა.
5. ნორმალიზაცია (MNIST-ის წესით): მელნის ზუსტი ჩარჩო → გრძელი მხარე 20 px-მდე **პროპორციის შენარჩუნებით** → 4×4 ქვეწერტილით გასაშუალოება (ნაცრისფერი კიდეები) → მასის ცენტრი 28×28 ველის ცენტრში.
6. ინფერენსი: Softmax, ციფრი = argmax, სანდოობა = max·100%; კოდის სანდოობა = 5 ციფრის საშუალო.
7. პოზიცია, სადაც მელანი საერთოდ არ არის, ბრუნდება **ცარიელად** (სანდოობა 0). ციფრი არასდროს გამოიგონება; გამყიდველი თავად შეიყვანს.

## 4. UI

- 5 უჯრა: ავტომატური გადასვლა, Backspace/Delete შუა უჯრაში სხვების გადაადგილების გარეშე, ისრები, Home/End, 5 ციფრის ჩასმა, არაციფრის უარყოფა.
- ნებისმიერი ციფრი < 70% → გაფრთხილება პოზიციით (მაგ. „საეჭვო ციფრები: #3 („7“, 45%)“). საშუალო ცალკე ცუდ ციფრს აღარ მალავს.
- ყოველი გახსნა სუფთაა. „დადასტურება“ ჩანს მხოლოდ უჯრებში მდგარი კოდის პროდუქტისთვის (ძველი ძებნის პასუხი იგნორირდება).
- კოდი მოიძებნება კატალოგში (`products:lookupCode`); ნაჩვენებია სახელი, ვარიანტი, ფასი, მარაგი → „დადასტურება“.
- კამერა: Electron აძლევს მხოლოდ ვიდეოს ნებართვას და მხოლოდ პროგრამის გვერდს. რამდენიმე კამერიდან არჩეული ახსოვს ამ კომპიუტერზე. დაბლოკილი, დაკავებული, არარსებული ან გათიშული კამერისას ჩანს ინსტრუქცია და „ხელახლა ცდა“. ფანჯრის დახურვისას კამერა ყოველთვის ითიშება (გვიან ჩართულიც).
