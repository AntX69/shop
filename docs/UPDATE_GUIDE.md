# StorePOS — განახლების გზამკვლევი

განახლება მონაცემებს არ შლის: ინსტალერი ცვლის მხოლოდ პროგრამის ფაილებს, ხოლო `%APPDATA%\StorePOS` ხელუხლებელი რჩება. ახალი ვერსია პირველ გაშვებაზე ბაზას ავტომატურად აახლებს და მანამდე ქმნის ასლს `store.db.before_migration_vN_<დრო>.bak`.

## 1. განახლებამდე

1. Owner-ით: **პარამეტრები → სარეზერვო ასლის შექმნა ახლავე**.
2. დააკოპირე ეს `.posbackup` ფაილი USB-ზე (ან გამოიყენე ავტომატური USB საქაღალდე).
3. დახურე StorePOS (ფანჯრის დახურვა საკმარისია).

## 2. განახლება

1. გაუშვი ახალი `StorePOS-Setup-<ვერსია>.exe`.
2. აირჩიე **იგივე** საქაღალდე, სადაც ძველი ვერსიაა.
3. გახსენი StorePOS და შედი ჩვეული PIN-ით.

## 3. შემოწმება

- პროდუქციის რაოდენობა, დღევანდელი გაყიდვები, ერთი-ორი კლიენტის ნისია — როგორც განახლებამდე.
- ფინანსები → „დღეს“.
- პარამეტრები → ასლების სია: გამოჩნდება ახალი ასლები.

## 4. თუ რამე არასწორადაა (უკან დაბრუნება)

1. დახურე StorePOS. **არაფერი წაშალო** `%APPDATA%\StorePOS`-ში.
2. დააინსტალირე წინა ვერსიის ინსტალერი იმავე საქაღალდეში.
3. პარამეტრები → „ფაილიდან აღდგენა…“ → აირჩიე განახლებამდე გაკეთებული `.posbackup`.

> ახალი ვერსიის შექმნილ ასლს ძველი ვერსია არ აღადგენს („ასლი შექმნილია უფრო ახალი ვერსიით“) — ეს დაცვაა, რომ უცნობი სტრუქტურის ბაზა არ გაიხსნას. ამიტომ უკან დასაბრუნებლად გამოიყენე **განახლებამდე** გაკეთებული ასლი.

## 5. ახალ კომპიუტერზე გადატანა

1. ძველ კომპიუტერზე: ასლის შექმნა → USB.
2. ახალზე: StorePOS-ის დაყენება → პირველ გაშვებაზე შექმენი **დროებითი** Owner (ნებისმიერი სახელით/PIN-ით).
3. პარამეტრები → „ფაილიდან აღდგენა…“ → USB-ის ფაილი.
4. აღდგენის შემდეგ პროგრამა ითხოვს ხელახლა შესვლას — შედი **ძველი** Owner-ის PIN-ით (დროებითი Owner აღარ არსებობს).

## 6. დეველოპერისთვის

- ბაზის ცვლილება მხოლოდ ახალი ვერსიის მიგრაციით (`src/main/db/migrations.ts`), ძველი მიგრაციების შეცვლის გარეშე.
- `package.json`-ის `version` ყოველ რელიზზე იზრდება; ინსტალერის სახელი მას მიჰყვება.
- რელიზამდე: `npm test`, `npm run dist:win`, E2E (`docs/release/TEST_REPORT.md`) და `e2e/upgrade` წინა ვერსიის მონაცემებით.
