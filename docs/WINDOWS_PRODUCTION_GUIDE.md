# StorePOS — Windows Production Release (M9) სახელმძღვანელო

ეს დოკუმენტი წარმოადგენს **StorePOS**-ის Windows 10/11 x64 ოფლაინ დესკტოპ აპლიკაციის საწარმოო (Production) გამოშვების, ინსტალაციის, მონაცემთა უსაფრთხოებისა და განახლების ოფიციალურ სახელმძღვანელოს.

---

## 1. Production Build Pipeline და კომპილაციის არქიტექტურა

StorePOS აგებულია **Electron + React + TypeScript + SQLite (WAL mode)** არქიტექტურაზე. საწარმოო პაკეტში აპლიკაცია მუშაობს **100% დამოუკიდებლად, სრულად ოფლაინ**, Express სერვერის ან `localhost:3000`-ის გარეშე.

### კომპილაციის ბრძანებები (`package.json`):
- `npm run build` — აკომპილირებს React/Vite კლიენტს (`dist/`) შეფარდებითი ბმულებით (`base: './'`) და `esbuild`-ით აკომპილირებს Electron Main Process-სა და Preload-ს (`dist-electron/main.cjs` და `dist-electron/preload.cjs`).
- `npm run pack` — ქმნის დამოუკიდებელ Windows x64 გაშვებად საქაღალდეს (`release/win-unpacked/`).
- `npm run dist:win` — აკომპილირებს სრულ პროექტს და ქმნის ოფიციალურ NSIS ინსტალერს (`StorePOS-Setup-1.0.0.exe`).
- `npm test` — უშვებს მთლიან სატესტო პაკეტს (32 ინტეგრაციული და ერთეულოვანი ტესტი).

### უსაფრთხოების პარამეტრები (Security Hardening):
- `contextIsolation: true` — Renderer ფანჯარას არ აქვს პირდაპირი წვდომა Node.js-ის შიდა API-ებზე.
- `nodeIntegration: false` — გამორიცხავს XSS შეტევებისას სისტემური ბრძანებების გაშვების რისკს.
- `sandbox: true` — Chromium-ის ქვიშის ყუთი (Sandboxing) გააქტიურებულია.
- `webSecurity: true` — ჩართულია მკაცრი ლოკალური ფაილური პოლიტიკა.
- **Single Instance Lock**: უზრუნველყოფს, რომ ერთ კომპიუტერზე ერთდროულად მხოლოდ ერთი StorePOS პროცესი მუშაობდეს, რაც გამორიცხავს SQLite ბაზის კონფლიქტურ ჩაწერას.

## 3. Windows კომპიუტერზე გაშვების ინსტრუქცია

### ვარიანტი A: Standalone / Portable რეჟიმში გაშვება (მყისიერი)
1. გადმოწერეთ `release/win-unpacked/` საქაღალდე ან ამოაარქივეთ `StorePOS-Setup-1.0.0.zip`.
2. ორჯერ დააკლიკეთ `StorePOS.exe`-ს.
3. პროგრამა გაიხსნება მყისიერად, Node.js-ის, npm-ის ან ინტერნეტის გარეშე.

### ვარიანტი B: NSIS საინსტალაციო ფაილის (`StorePOS-Setup-1.0.0.exe`) აწყობა Windows-ზე
თუ გსურთ ოფიციალური `.exe` ინსტალერის დაგენერირება უშუალოდ თქვენს Windows კომპიუტერზე:
1. გადმოწერეთ პროექტის კოდი Windows მანქანაზე.
2. გახსენით ტერმინალი (cmd ან PowerShell) პროექტის საქაღალდეში.
3. გაუშვით:
   ```cmd
   npm install
   npm run dist:win
   ```
4. `release/` საქაღალდეში დაგენერირდება `StorePOS-Setup-1.0.0.exe`.

### ინსტალერის მახასიათებლები:
- **Desktop Shortcut** (დესკტოპის მალსახმობი მაღაზიის ლოგოთი).
- **Start Menu Shortcut** (დაწყების მენიუს მალსახმობი).
- **Custom Installation Directory** (ინსტალაციის საქაღალდის არჩევა: `C:\Program Files\StorePOS` ან მომხმარებლის მიერ მითითებული ნებისმიერი დისკი).
- **Uninstall Safeguard** (`deleteAppDataOnUninstall: false`): პროგრამის წაშლისასაც კი მომხმარებლის მონაცემთა ბაზა და ფოტოები არ იშლება.

## 4. მონაცემთა უსაფრთხო შენახვა (Persistent Storage)

მონაცემები ინახება ოპერაციული სისტემის მომხმარებლის უსაფრთხო გარემოში (`userData`):
- **მდებარეობა Windows-ზე:** `%APPDATA%\StorePOS\data\`
  - `store.db` — SQLite მონაცემთა ბაზა (WAL + Foreign Keys).
  - `images/` — პროდუქციის ატვირთული რეალური ფოტოები.
  - `backups/` — სისტემის მიერ ავტომატურად ან ხელით გენერირებული `.posbackup` და `.bak` ფაილები.

### SQLite Durability გადაწყვეტილება (`synchronous = FULL`):
M8 ეტაპზე გამოყენებული იყო `synchronous = NORMAL`. M9 საწარმოო რელიზში ფინანსური ოპერაციების მაქსიმალური მდგრადობისთვის მიღებულია გადაწყვეტილება:
- **`PRAGMA synchronous = FULL;`**
- **არგუმენტაცია:** არასასურსათო მაღაზიის სალაროში ყოველი ტრანზაქციის დროს ხდება რეალური ნაღდი ფულის მიღება, ხურდის დაბრუნება ან ნისიის დაფიქსირება. ელექტროენერგიის მოულოდნელი გათიშვის (Power Outage) ან კომპიუტერის კვების ბლოკის გათიშვის შემთხვევაში, `synchronous = FULL` უზრუნველყოფს, რომ SQLite-მა დაუყოვნებლივ შეასრულოს `fsync()` დისკის ფიზიკურ ფენაზე. ეს გამორიცხავს ნებისმიერი დასრულებული გაყიდვის ან ნისიის დაფარვის დაკარგვას.

## 5. პირველი გაშვება (First-Run Wizard)

სუფთა ინსტალაციისას (როდესაც `%APPDATA%\StorePOS\data\store.db` ჯერ არ არსებობს):
1. აპლიკაცია ავტომატურად ქმნის საჭირო ქვესაქაღალდეებს (`data`, `images`, `backups`).
2. ეშვება SQLite მიგრაციები და იქმნება ცარიელი, სუფთა სქემა.
3. სისტემა ამოწმებს `hasOwner()`-ს. რადგან მფლობელი ჯერ არ არსებობს, ეკრანზე ჩნდება **„მფლობელის პირველადი რეგისტრაციის“** ფანჯარა.
4. მფლობელი უთითებს თავის სახელს და ირჩევს 4-დან 6 ციფრამდე PIN კოდს.
5. საინსტალაციო პაკეტში **არ არის ჩართული არანაირი სატესტო ან დემო მონაცემი** — მაღაზია იწყებს მუშაობას სუფთა ფურცლიდან.

## 6. უსაფრთხო განახლების პროცედურა (Zero Data Loss Upgrades)

როდესაც მომავალში გამოვა StorePOS-ის ახალი ვერსია (მაგ. v1.1.0):
1. **მონაცემთა ავტომატური ხელშეუხებლობა:** ახალი ინსტალერის გაშვება აახლებს მხოლოდ პროგრამულ კოდს (`app.asar` და ბინარულ ფაილებს ინსტალაციის დირექტორიაში). მონაცემთა ბაზა და ფოტოები იმყოფება `%APPDATA%\StorePOS\data\`-ში და რჩება ხელუხლებელი.
2. **ავტომატური უსაფრთხოების ასლი მიგრაციის წინ:** ახალი ვერსიის პირველი გაშვებისას, თუ სქემა შეიცვალა, მიგრატორი ავტომატურად ქმნის ფაილს:
   `store.db.before_migration_vX_<timestamp>.bak`
3. **Emergency Pre-Reset Backup:** მფლობელის მიერ ბაზის გასუფთავების მოთხოვნის შემთხვევაშიც კი, სისტემა ჯერ ავტომატურად ინახავს საგანგებო ასლს `backups/` საქაღალდეში.

## 7. 100% ოფლაინ OCR მოდული

- **მოდელი:** `mnist.onnx` შეფუთულია პირდაპირ `resources/models/mnist.onnx`-ში.
- **ინფერენსი:** ხორციელდება ლოკალურად Electron Main Process-ში `onnxruntime-web`-ის CPU/WASM ძრავით.
- **კამერის გარეშე მუშაობა:** თუ კომპიუტერს არ გააჩნია ვებკამერა, პროგრამა მუშაობს სრულიად შეუფერხებლად USB შტრიხკოდის სკანერითა და 5-ნიშნა კოდების ხელით შეყვანით.
