# USB შტრიხკოდის სკანერი: მომზადება და შემოწმება

**სტატუსი: Software Verified / Hardware Pending.** პროგრამული მხარე შემოწმებულია რეალურ StorePOS.exe-ში. ტესტი სკანერის სიჩქარით აგზავნის კლავიშების დაჭერებს Chromium-ის შეყვანის გზით (`e2e/hardware-readiness.mjs`) და იყენებს unit ტესტებს (`scannerInput.test.ts`). ფიზიკური სკანერი ჯერ არ შემოწმებულა.

## 1. რომელი სკანერი ვიყიდო

| მოთხოვნა | რატომ |
|---|---|
| **USB, „HID Keyboard“ (კლავიატურის ემულაცია)** | StorePOS სკანერს კლავიატურად კითხულობს. დრაივერი არ სჭირდება. |
| 1D კოდები: EAN-13, EAN-8, UPC-A/E, Code 128, ITF | მაღაზიის საქონლის უმეტესობაზე EAN-13-ია. |
| სუფიქსი **Enter (CR)** ქარხნულად ან კონფიგურაციის კოდით | სკანირება Enter-ით სრულდება. Tab-იც მუშაობს. |
| სასურველია: Bluetooth/უსადენოც, თუ HID რეჟიმი აქვს | ასეთი სკანერი იგივე კლავიატურაა. |

**არ გამოდგება:** სკანერი, რომელიც მხოლოდ „USB COM / Virtual Serial Port“ რეჟიმში მუშაობს. StorePOS COM პორტს არ კითხულობს. ბევრ სკანერს ორივე რეჟიმი აქვს: აირჩიე HID Keyboard.

შენიშვნა: პროდუქტის შტრიხკოდი StorePOS-ში მხოლოდ ციფრებისგან შედგება (წამყვანი ნულების ჩათვლით). ასოებიანი კოდი (მაგ. Code 39-ით ჩაწერილი სტატია) პროდუქტს არ ემთხვევა და სალარო ამას შეტყობინებით გაჩვენებს.

## 2. პირველი შეერთება (5 წუთი)

1. შეაერთე სკანერი USB-ში. Windows მას კლავიატურად ცნობს, რამდენიმე წამში.
2. გახსენი **Notepad** და დაასკანერე ნებისმიერი საქონლის შტრიხკოდი.
   - ციფრები ჩაიწერა და კურსორი **ახალ ხაზზე** გადავიდა → სკანერი HID რეჟიმშია, Enter სუფიქსით. ✅
   - ციფრები ჩაიწერა, ახალი ხაზი არ ჩანს → სუფიქსი არ არის. სკანერის სახელმძღვანელოში მოძებნე „Add Suffix CR“ / „Enter“ და დაასკანერე ის კონფიგურაციის კოდი. სუფიქსის გარეშეც იმუშავებს: StorePOS 0,15 წამს დაელოდება.
   - არაფერი ჩაიწერა → სკანერი სხვა რეჟიმშია (COM). სახელმძღვანელოში მოძებნე „USB HID Keyboard“.
   - სხვა სიმბოლოები ჩაიწერა ციფრების ნაცვლად (მაგ. `&é"`) → სკანერზე კლავიატურის ქვეყანა (Keyboard Country) დააყენე **USA**.
3. დახურე Notepad შენახვის გარეშე.

## 3. როგორ მუშაობს StorePOS-ში

StorePOS სკანერს სიჩქარით ცნობს: სკანერი ციფრებს ძალიან სწრაფად ბეჭდავს, ადამიანი კი ვერა. ამიტომ:

| სიტუაცია | რა ხდება |
|---|---|
| სალაროს ეკრანი, ფოკუსი ნებისმიერ ადგილას (ძებნის ველი, კალათის „+“ ღილაკი, ცარიელი ადგილი) | კოდი იძებნება. იხსნება **პროდუქტის დადასტურების** ფანჯარა. სკანერის Enter არცერთ ღილაკს არ „აჭერს“. |
| კალათაში დამატება | მხოლოდ გამყიდველის დაჭერით: **„კალათაში დამატება“**. სკანერის Enter დადასტურებად არ ითვლება. |
| დადასტურების ფანჯარა ღიაა, იგივე პროდუქტი დაასკანერე | რაოდენობა +1 (წარწერა: „იგივე პროდუქტი კიდევ ერთხელ“), მარაგის ფარგლებში. |
| დადასტურების ფანჯარა ღიაა, სხვა პროდუქტი დაასკანერე | ახალი პროდუქტი **რიგში დგება** („რიგში კიდევ 1“), არ ანაცვლებს ღიას. დადასტურების ან გაუქმების შემდეგ თავისით გაიხსნება, დასკანერებული რაოდენობით. |
| დადასტურების ფანჯარაში რაოდენობის ველია აქტიური და დაასკანერე | ციფრები ველში **არ** ჩაიწერება, სკანი ჩვეულებრივად მუშავდება. |
| უცნობი შტრიხკოდი | „დასკანერებული კოდი „…“ ბაზაში ვერ მოიძებნა“. არაფერი იხსნება და არაფერი ემატება. |
| გადახდის ფანჯარა ღიაა | სკანი **არ** მუშავდება და ეკრანზე ჩანს რატომ. დახურე ფანჯარა (Esc) და დაასკანერე თავიდან. |
| ჩეკის ფანჯარა ღიაა (გაყიდვა დასრულდა) | ჩეკი იხურება და იწყება ახალი გაყიდვა დასკანერებული პროდუქტით. |
| კამერის ფანჯარა ღიაა | კამერა ითიშება და დასკანერებული პროდუქტი იხსნება. |
| ჩანართი „პროდუქცია“ → ახალი პროდუქტი → „ქარხნული შტრიხკოდი“ ველი | კოდი ველში ჩაიწერება. სკანერის Enter ფორმას **არ აგზავნის**. |
| წამყვანი ნულები (მაგ. `0004006381333`) | ინახება და იძებნება ზუსტად ისე, როგორც არის. |
| Windows-ის ენა ქართული/რუსული/ინგლისური, NumLock გამორთული | შედეგზე გავლენა არ აქვს: StorePOS ფიზიკურ კლავიშს კითხულობს. |
| CR+LF სუფიქსი (ორი Enter) | მეორე Enter იგნორირდება. |

ხელით აკრეფა ისევ მუშაობს: ძებნის ველში კოდის ან სახელის აკრეფა და Enter.

## 4. სკანერის შემოწმება, როცა მოწყობილობა გექნება (≈15 წუთი)

მოამზადე 3–4 პროდუქტი რეალური შტრიხკოდით, მათ შორის ერთი 0-ით დაწყებული. თითოეული პუნქტი მონიშნე ✅ ან ❌.

| # | მოქმედება | მოსალოდნელი შედეგი |
|---|---|---|
| 1 | Notepad-ის ტესტი (§2) | ციფრები + ახალი ხაზი |
| 2 | სალარო → დაასკანერე პროდუქტი | დადასტურების ფანჯარა სწორი სახელით, ფასით და მარაგით |

| 4 | დააჭირე კალათის „+“-ს, შემდეგ დაასკანერე სხვა პროდუქტი | იხსნება ახალი პროდუქტი; „+“ მეორედ **არ** დაჭერილა |

| 7 | 0-ით დაწყებული შტრიხკოდი | პოულობს; ფანჯარაში კოდი ნულებით ჩანს |
| 8 | ბაზაში არარსებული კოდი (მაგ. სხვა მაღაზიის საქონელი) | „…ბაზაში ვერ მოიძებნა“ |
| 9 | 10 სწრაფი სკანი ზედიზედ (2 პროდუქტი მონაცვლეობით) | ორი ფანჯარა თანმიმდევრობით, სულ 10 ცალი; არაფერი დაიკარგა ან გაორმაგდა |

| 11 | გადახდის ფანჯარაში დაასკანერე | შეტყობინება, კალათა უცვლელი |

| სიმპტომი | მიზეზი და გამოსავალი |

## 6. რა დარჩა მოწყობილობაზე შესამოწმებელი

- კონკრეტული მოდელის სიჩქარე, სუფიქსი და კლავიატურის ქვეყანა.
- წაკითხვის ხარისხი ნამდვილ ეტიკეტებზე (მბზინავი, მოხრილი, წვრილი).
- უსადენო სკანერის ქცევა მანძილზე და ბატარეის დაჯდომისას.

სანამ ეს შემოწმება არ ჩატარდება, სტატუსი რჩება **Hardware Pending**.
