# StorePOS: სარეზერვო ასლები და მონაცემების აღდგენა (Disaster Recovery)

მოკლე გზამკვლევი მაღაზიისთვის: როგორ არ დაიკარგოს მონაცემები და რა ვქნა, თუ კომპიუტერს რამე დაემართა.

## 1. სად ინახება მონაცემები

| რა | სად |
|---|---|
| ბაზა (გაყიდვები, ნისიები, მარაგი, ფინანსები, მომხმარებლები) | `%APPDATA%\StorePOS\data\store.db` (+ `store.db-wal`, `store.db-shm`) |
| პროდუქტების ფოტოები | `%APPDATA%\StorePOS\data\images\` |
| სარეზერვო ასლები | `%APPDATA%\StorePOS\data\backups\` ან პარამეტრებში არჩეული საქაღალდე |
| დამატებითი ასლი | პარამეტრებში არჩეული „დამატებითი საქაღალდე“ (USB დისკი) |

ერთი `.posbackup` ფაილი შეიცავს **ყველაფერს**: ბაზას, ყველა ფოტოს და პარამეტრებს. ფაილში ჩაწერილია SHA-256 საკონტროლო ჯამი ბაზისთვის და თითოეული ფოტოსთვის.

## 2. ავტომატური ასლი: როგორ მუშაობს

- პროგრამის ჩართვიდან **1 წუთში** და შემდეგ **ყოველ 30 წუთში** ამოწმებს, გაკეთდა თუ არა დღეს ასლი. თუ არა, აკეთებს.
- ანუ: **დღეში ერთი ავტომატური ასლი**. კომპიუტერის გადატვირთვის შემდეგაც: პროგრამის ჩართვიდან 1 წუთში.
- თუ სალარო შუაღამის მერეც ღიაა, ახალი დღის ასლი 30 წუთში გაკეთდება.
- ინახება ბოლო 30 ავტომატური ასლი (რაოდენობა იცვლება პარამეტრებში). ძველები ავტომატურად იშლება. ხელით გაკეთებული და აღდგენამდე შექმნილი ასლები **არასდროს** იშლება.
- USB დისკზე ასლი ფონურ რეჟიმში იწერება: ნელი USB სალაროს მუშაობას არ აფერხებს.

**მნიშვნელოვანი:** ავტომატური ასლი დღის დასაწყისშია, ამიტომ დღის ბოლოს გაკეთებული გაყიდვები მომდევნო დილამდე ასლში არ ხვდება. **დღის ბოლოს**: პარამეტრები (F8) → „სარეზერვო ასლის შექმნა ახლავე“. USB მიერთებული უნდა იყოს.

## 3. ყოველდღიური / ყოველკვირეული წესი

1. USB დისკი სალაროს კომპიუტერთან მიერთებული იყოს (პარამეტრებში არჩეული „დამატებით საქაღალდედ“).
2. დღის ბოლოს: „სარეზერვო ასლის შექმნა ახლავე“. შეტყობინებაში უნდა ეწეროს „ასლი ასევე ჩაიწერა: E:\...“.
3. კვირაში ერთხელ: USB წაიღე სახლში ან შეინახე სხვაგან (ხანძრის/ქურდობის შემთხვევისთვის). ან იქონიე ორი USB და მონაცვლეობით გამოიყენე.
4. თვეში ერთხელ: პარამეტრებში ბოლო ასლზე დააჭირე „შემოწმება“. უნდა ეწეროს „მთლიანობა დადასტურებულია“.

**კონფიდენციალურობა:** ასლში არის მომხმარებლების სახელები, ტელეფონები და ნისიები, ასევე PIN-ების ჰეშები (თავად PIN-ები არა). USB შეინახე უსაფრთხოდ. ასლი **არასდროს** ატვირთო GitHub-ზე ან სხვა საჯარო ადგილას. თუ ასლების საქაღალდედ OneDrive-ის საქაღალდეს აირჩევ (მაგ. Desktop, Documents), ასლები Microsoft-ის ღრუბელშიც აიტვირთება. ეს შენი გადაწყვეტილებაა.

## 4. სცენარები

### A. კომპიუტერი გაფუჭდა, დისკი დაზიანდა ან Windows თავიდან ჩაიდგა

1. ახალ (ან შეკეთებულ) კომპიუტერზე დააყენე StorePOS (იხ. [INSTALL_AND_BACKUP_KA.md](INSTALL_AND_BACKUP_KA.md)).
2. პირველ გაშვებაზე შექმენი **დროებითი** მფლობელი: ნებისმიერი სახელი, ნებისმიერი PIN.
3. USB-დან `.posbackup` ფაილი (ყველაზე ბოლო) დააკოპირე კომპიუტერზე.
4. პარამეტრები (F8) → „ფაილიდან აღდგენა…“ → აირჩიე ფაილი → დაადასტურე.
5. პროგრამა მოითხოვს ხელახლა შესვლას. შედი **ძველი მფლობელით და ძველი PIN-ით**. დროებითი მფლობელი აღარ არსებობს.
6. შეამოწმე: პროდუქტები და ფოტოები, ნაშთები, ნისიები (ნისიების გვერდი), ფინანსები → „ყველა“.

ეს გზა რეალურ პროგრამაში გამოცდილია ორ ცალკე პროფილზე („მაღაზიის“ და „ახალი“ კომპიუტერი): მომხმარებლები, პროდუქტები, ნაშთები, ნისიები, გაყიდვები, ფინანსები და ფოტოები (ბაიტ-ბაიტ) ზუსტად აღდგა (`e2e/dr-restore-test.mjs`). ფიზიკურად მეორე კომპიუტერზე ჯერ არ შემოწმებულა.

### B. შეცდომით რაღაც წაიშალა ან არასწორად შეიცვალა

1. პარამეტრები → ასლების სია → აირჩიე ასლი შეცდომამდე → „აღდგენა“.
2. აღდგენამდე პროგრამა **ავტომატურად** ინახავს მიმდინარე მდგომარეობას (`storepos_prerestore_...`). თუ აღმოჩნდა, რომ არასწორი ასლი აღადგინე, აღადგინე ეს ფაილი და დაბრუნდები იქ, სადაც იყავი.
3. ყურადღება: ასლის შემდეგ გაკეთებული გაყიდვები აღდგენისას ქრება (ისინი რჩება prerestore ფაილში).

### C. პროგრამა არ ირთვება: „მონაცემთა ბაზა ვერ გაიხსნა“

1. **არაფერი წაშალო.** გადატვირთე კომპიუტერი და სცადე თავიდან. თუ სხვა პროგრამა იყო ბაზაზე მიბმული, ეს საკმარისია.
2. თუ ისევ არ ირთვება: დახურე StorePOS. მთლიანი საქაღალდე `%APPDATA%\StorePOS\data` დააკოპირე USB-ზე (Win+R → `%APPDATA%\StorePOS` → Enter).
3. ამავე საქაღალდეში `store.db`, `store.db-wal` და `store.db-shm` გადაარქვი, მაგ. `store.db.damaged` (არ წაშალო!).
4. ჩართე StorePOS: დაიწყება როგორც ახალი. შექმენი დროებითი მფლობელი და აღადგინე ბოლო ასლი, როგორც სცენარ A-ში (ასლები იმავე `data\backups` საქაღალდეშია).
5. დაზიანებული ფაილი შეინახე: შეიძლება მისგან ბოლო გაყიდვების ამოღება ტექნიკოსმა სცადოს.

შენიშვნა: ამ შემთხვევაში აღდგენა ფაილების ხელით გადარქმევას მოითხოვს, რადგან პროგრამა დაზიანებულ ბაზაზე არ ირთვება. ეს განზრახ არის ასე: პროგრამა დაზიანებულ ფაილს არც ცვლის, არც შლის (შემოწმებულია, `e2e/restart-test.mjs`).

### D. USB დისკი არ არის მიერთებული ან სავსეა

- ძირითადი ასლი მაინც იწერება კომპიუტერზე. პარამეტრებში ჩანს მიზეზი: „საქაღალდე/დისკი ხელმისაწვდომი არ არის“ ან „დისკზე ადგილი აღარ არის“.
- ნახევრად ჩაწერილი ფაილი არ რჩება. მიაერთე USB (ან გაათავისუფლე ადგილი) და გააკეთე „სარეზერვო ასლის შექმნა ახლავე“.

### E. კომპიუტერის დისკი სავსეა

- ასლი არ იწერება და ჩანს შეტყობინება: რამდენი MB სჭირდება და რამდენია თავისუფალი. წინა ასლები და ბაზა ხელუხლებელია.
- გაათავისუფლე ადგილი (ან შეამცირე შესანახი ავტომატური ასლების რაოდენობა პარამეტრებში) და გააკეთე ასლი ხელახლა.

### F. დაზიანებული ასლის ფაილი

- აღდგენამდე პროგრამა ამოწმებს ფორმატს, ბაზის SHA-256-ს და SQLite-ის `integrity_check`-ს. დაზიანებულ ასლს **უარყოფს** და მიმდინარე მონაცემებს არ ეხება. აიღე წინა დღის ასლი.
- თუ დაზიანებულია მხოლოდ ერთი ფოტო, ბაზა აღდგება, ეს ფოტო გამოტოვდება და შეტყობინება გეტყვის, რამდენი ფოტოა დასამატებელი თავიდან.

## 5. პროგრამის განახლება და Windows Update

- Windows Update `%APPDATA%\StorePOS`-ს არ ეხება.
- StorePOS-ის ახალი ვერსიის დაყენება ძველის თავზე მონაცემებს ინახავს. ეს შემოწმებულია ინსტალერის ციკლით: იმავე ვერსიის ზემოდან დაყენება, ძველი ვერსიის თავზე ახლის დაყენება და წაშლა. **განახლებამდე მაინც გააკეთე ასლი USB-ზე** (იხ. [UPDATE_GUIDE.md](UPDATE_GUIDE.md)).
- პროგრამის წაშლა (Uninstall) მონაცემებს არ შლის.

## 6. რა არ არის ასლში

- თავად პროგრამა: ინსტალერი (`StorePOS-Setup-….exe`) შეინახე ცალკე, იმავე USB-ზე.
- Windows-ის პარამეტრები, სკანერის კონფიგურაცია, კამერის არჩევანი (თავიდან აირჩევ).
- ასლის შემდეგ გაკეთებული ცვლილებები.
